**A. Loader**
Place the cut-1 loader in `project/plugins/App.Resource.Bundle.Seam/CommonResidentLayer/`, not `App.Common`: `App.Common` is explicitly still exe cargo for this phase, but may later move, while `App.Resource(+Bundle.Seam)` is part of the loading floor; also `App.Resource.Bundle.Seam` already references `App.Common`, so putting this in `App.Common` would point the dependency the wrong way (`vault/specs/2026-07-08-common-resident-layer-bundle.md:51`, `vault/specs/2026-07-08-common-resident-layer-bundle.md:54`, `project/plugins/App.Resource.Bundle.Seam/App.Resource.Bundle.Seam.csproj:19`).

Add `CommonResidentLayerBootstrap.EnsureLoaded()` and call it as the first statement of `Host._Ready`, before `GD.Print`, `AppComposition.Activate()`, `BuildPluginHost`, and all composition calls (`project/hosts/complete-app/Host.cs:45`, `project/hosts/complete-app/Host.cs:49`, `project/hosts/complete-app/Host.cs:54`, `project/hosts/complete-app/Host.cs:66`). This is early enough because E2 proved first demand is late enough for a first-statement `_Ready` hook, and the micro-bootstrap is only needed when moving `App.Common` or kernel code too (`vault/specs/2026-07-08-common-resident-layer-bundle.md:122`, `vault/specs/2026-07-08-common-resident-layer-bundle.md:127`, `vault/specs/2026-07-08-common-resident-layer-bundle.md:129`, `vault/specs/2026-07-08-common-resident-layer-bundle.md:131`).

`EnsureLoaded()` installs `AssemblyLoadContext.Default.Resolving`, locates `<AppContext.BaseDirectory>/bundles/common.pck` using the existing exe-adjacent bundle convention, then loads the PCK with `BundleVfs.LoadPck()` or `ProjectSettings.LoadResourcePack` (`Taskfile.yml:208`, `Taskfile.yml:223`, `Taskfile.yml:229`, `project/plugins/App.Resource.Bundle.Seam/BundleVfs.cs:8`). It mounts as `res://bundles/common`, matching existing bundle path derivation (`project/plugins/App.Resource.Bundle.Seam/BundleHost.cs:166`, `project/plugins/App.Resource.Bundle.Seam/BundleHost.cs:167`).

Extend `BundleExtractor` with `ExtractAllManaged(string bundleResPath, IReadOnlyList<string> expectedDlls)`: reuse its temp-root/session strategy, Godot `FileAccess` byte copy, and DLL visitor rule, but return every extracted DLL path instead of only `PluginAssemblyPath` (`project/plugins/App.Resource.Bundle.Seam/BundleExtractor.cs:13`, `project/plugins/App.Resource.Bundle.Seam/BundleExtractor.cs:20`, `project/plugins/App.Resource.Bundle.Seam/BundleExtractor.cs:26`, `project/plugins/App.Resource.Bundle.Seam/BundleExtractor.cs:105`, `project/plugins/App.Resource.Bundle.Seam/BundleExtractor.cs:116`, `project/plugins/App.Resource.Bundle.Seam/BundleExtractor.cs:155`). Preload every manifest DLL into `AssemblyLoadContext.Default.LoadFromAssemblyPath` before `AppComposition.Activate()`; the resolving hook maps any missed `AssemblyName.Name` to the extracted path (`vault/specs/2026-07-08-common-resident-layer-bundle.md:95`, `vault/specs/2026-07-08-common-resident-layer-bundle.md:98`, `project/plugins/App.Common/AppComposition.cs:24`, `project/plugins/App.Common/AppComposition.cs:26`).

This avoids the E1 crash pattern because it does not introduce a greenfield exported host or reflection bootstrap that runs before `_Ready`; E1 crashed in CoreCLR class init before `_Ready` and before PCK access, while this runs inside the existing autoloaded `Host` and reuses the daily bundle path: `LoadPck`, read manifest, extract via `BundleExtractor`, then explicit load (`vault/specs/2026-07-08-common-resident-layer-bundle.md:112`, `vault/specs/2026-07-08-common-resident-layer-bundle.md:115`, `vault/specs/2026-07-08-common-resident-layer-bundle.md:119`, `project/hosts/complete-app/project.godot:12`, `project/hosts/complete-app/project.godot:16`, `project/plugins/App.Resource.Bundle.Seam/BundleHost.cs:169`, `project/plugins/App.Resource.Bundle.Seam/BundleHost.cs:203`, `project/plugins/App.Resource.Bundle.Seam/BundleHost.cs:215`).

Failure mode: missing `common.pck`, missing manifest, missing DLL, version/hash mismatch, or extraction/load failure is boot-fatal. Because `_log` does not exist until after `AppComposition.Activate()`, failure reporting must use `GD.PrintErr` plus a Godot alert, then throw `InvalidOperationException` before composition (`project/hosts/complete-app/Host.cs:49`, `project/hosts/complete-app/Host.cs:50`). Idempotency: static lock, `_loaded` flag, single hook registration, and skip already loaded assemblies only when name/version/hash match.

**D. Version Gate**
Expectation lives in generated `<exeDir>/config/common-resident-expected.json`, not only in `.deps.json`: `.deps.json` supplies compile-time package/runtime names, but the generated file carries the exact common identity and hashes that the stripped exe expects (`tools/bundles/stage_bundle.py:46`, `tools/bundles/stage_bundle.py:52`, `vault/specs/2026-07-08-common-resident-layer-bundle.md:73`, `vault/specs/2026-07-08-common-resident-layer-bundle.md:75`). Loader compares expected `{ assemblyName, assemblyVersion, sha256 }` to `common.pck` manifest before any load; mismatch is boot-fatal. This matches the dormant catalog design’s `address -> location, hash, deps` direction without building remote providers yet (`vault/architecture/bundle-delivery-and-loading.md:64`, `vault/architecture/bundle-delivery-and-loading.md:66`, `vault/architecture/bundle-delivery-and-loading.md:72`, `vault/architecture/bundle-delivery-and-loading.md:81`).

**RISKS**
`LoadFromAssemblyPath` order may expose hidden dependency ordering bugs, so the manifest should preserve deps order and the resolving hook must remain installed before preload (`tools/bundles/stage_bundle.py:46`, `tools/bundles/stage_bundle.py:53`). Some “pure” NuGet assemblies may contain RID-specific managed assets, so the packer must hash-compare arm64 and x86_64 candidates before making one universal `common.pck` (`/Users/apprenticegc/Work/lunar-horse/plate-projects/unify-build/dotnet/src/UnifyBuild.Nuke/IUnifyGodot.cs:125`, `/Users/apprenticegc/Work/lunar-horse/plate-projects/unify-build/dotnet/src/UnifyBuild.Nuke/IUnifyGodot.cs:128`). Godot script registration from Default-loaded PCK assemblies remains unproven and explicitly out of scope (`vault/specs/2026-07-08-common-resident-layer-bundle.md:104`, `vault/specs/2026-07-08-common-resident-layer-bundle.md:107`).
